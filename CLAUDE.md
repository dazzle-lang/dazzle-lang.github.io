# dazzle-lang.github.io — notes for Claude Code

The Dazzle website: Astro + Starlight, deployed to GitHub Pages by
`.github/workflows/deploy.yml`. README.md says where every page comes from.

- **Never edit `src/content/docs/spec/` or `src/content/docs/decisions/`.** They are
  generated by `scripts/sync.mjs` from the Dazzle repository (`DAZZLE_REPO`, default
  `../Dazzle`) and ignored by git. Change the source there.
- **The language's facts come from the Dazzle spec**, not from memory: read the section
  before writing about a feature. The spec's own rules apply (its `CLAUDE.md`).
- **Every complete Dazzle program on a hand-written page must compile and run.** Check it
  with `dz run` before publishing; error messages shown on a page should be real `dz`
  output, not invented. That includes the playground's examples
  (`src/playground/examples/`), except `a-mistake.dz`, which must fail with exactly one
  error.
- **Comparison pages make claims about other languages.** Keep them to well-established
  facts and fair "choose X if" sections.
- Run `npm run build && npm run check` before finishing: the check fails on a broken
  internal link or heading anchor, which is how a change in Astro's heading ids would show.
- Dev server in the background: `npx astro dev --background`; manage it with `astro dev
  stop | status | logs`. Astro's docs: https://docs.astro.build
- Do not commit or push unless the user asks, and add no AI attribution to commits.
