**Dazzle 0.2 was released on 17 November 2026**, at revision r143 ([release notes and downloads](https://github.com/dazzle-lang/Dazzle/releases/tag/v0.2.0)). 0.1 was released on 4 November at r117, and this page is the record of how 0.2 was reached. The last revisions before the release ([changelog](/spec/21-changelog/)):
- `indexed()` is a value outside a loop's head (r138).
- A trait's method may be generic (r139).
- A C++ namespace may be named bare, `ImGui::Begin` (r141).
- Dependencies and C++ libraries may be fetched with git, pinned by a lockfile (r142).
- ImGui's `printf`-style functions, such as `ImGui::Text`, are callable (r143).

Every part of the plan is done. The [backlog](https://github.com/dazzle-lang/Dazzle/blob/master/docs/tasks.md) tracks what comes after.

## Automatic memory placement across calls

**Implemented in r119.** An allocation has a home in a region or on the heap. A `sends` clause tells callers where ownership can go, so the compiler can choose a home that lasts long enough. A helper can build directly into memory owned by its caller. Moving a value preserves the allocation. [Walk through the allocations](/tour/memory-placement/) · [D-0097](/decisions/d-0097-homes-ownership-that-travels-with-its/)

## 2. Faster builds

Unchanged builds can skip analysis. A body-only edit leaves dependent modules alone, and the build recompiles the C++ it needs. The standard library’s compiled C++ and precompiled declarations are shared across projects.

On the [100-module scale test](https://github.com/dazzle-lang/Dazzle/blob/master/tests/bench_programs/SCALE.md), the 14 November clang++ run took **8.18 s** from clean (C++: 5.20 s), **0.01 s** with no changes, and **0.88 s** after a one-line edit, ahead of the same program in C++ built by `make` (1.10 s). Both small-program build targets are met on Linux. Type-checking the standard library once rather than on every build, about 11 ms, needs its checked form kept on disk, and comes after 0.2.

## After 0.2

- **Packages:** a command that lists newer releases of a dependency pinned by `version` ([T-0244](https://github.com/dazzle-lang/Dazzle/blob/master/docs/tasks/T-0244-dz-lists-newer-releases-git-source.md)). The examples' other C libraries are to move off git submodules, as ImGui did.
- **Tools for LLMs:** a hint and a `dz fix` that shorten `imgui::ImGui::Text` to `ImGui::Text` where the namespace is named bare. Also an API dump of a module, and test output a program can parse.
- **Scale:** a game of ten thousand lines, to see how the safety rules hold in a large program, and fewer of the cases where the compiler still puts memory on the heap. Those cost speed, not safety.
- **Hot reload:** a rebuilt module swapped into a running game, keeping its state.
- **The editor:** incremental analysis, and the rest of the quick fixes.
- **Microcontrollers:** builds with no heap and no operating system, for boards such as an Arduino Uno and an STM32.
- **The web:** the same game running in a browser, through Emscripten.
- **Threads:** a mutex, atomics and a job system.

Not planned for now: **Jolt Physics**, the other C++ library once planned beside ImGui. The milestones are in [spec §19](/spec/19-roadmap/).
