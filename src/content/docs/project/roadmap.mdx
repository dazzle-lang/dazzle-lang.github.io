## Automatic memory placement across calls

**Implemented in r119.** An allocation has a home in a region or on the heap. A `sends` clause tells callers where ownership can go, so the compiler can choose a home that lasts long enough. A helper can build directly into memory owned by its caller. Moving a value preserves the allocation. [Walk through the allocations](/tour/memory-placement/) · [D-0097](/decisions/d-0097-homes-ownership-that-travels-with-its/)

## 2. Faster builds

Unchanged builds can skip analysis. A body-only edit leaves dependent modules alone, and the build recompiles the C++ it needs. The standard library’s compiled C++ and precompiled declarations are shared across projects.

On the [100-module scale test](https://github.com/dazzle-lang/Dazzle/blob/master/tests/bench_programs/SCALE.md), the 11 November clang++ run took **7.22 s** from clean, **0.01 s** with no changes, and **about 1 s** after a one-line edit. The two small-program build targets are already met on Linux. Work remains on reusing analysis and cleaning up generated files.

## 6. The release

Release notes from the [changelog](/spec/21-changelog/) since revision 117, which 0.1 carries. If there is time, dependencies fetched from git and pinned by a lockfile ([T-0077](https://github.com/dazzle-lang/Dazzle/blob/master/docs/tasks/T-0077-git-dependencies-pinned-by-lockfile.md)); otherwise they move to 0.3.

## After 0.2

- **Packages:** dependencies fetched from git, Dazzle packages and C libraries alike, pinned by a lockfile, if they miss 0.2.
- **Scale:** a game of ten thousand lines, to see how the safety rules hold in a large program, and fewer of the cases where the compiler still puts memory on the heap. Those cost speed, not safety.
- **Hot reload:** a rebuilt module swapped into a running game, keeping its state.
- **The editor:** incremental analysis, and the rest of the quick fixes.
- **Microcontrollers:** builds with no heap and no operating system, for boards such as an Arduino Uno and an STM32.
- **The web:** the same game running in a browser, through Emscripten.
- **Threads:** a mutex, atomics and a job system.

Not planned for now: **Jolt Physics**, the other C++ library once planned beside ImGui. The milestones are in [spec §19](/spec/19-roadmap/).
