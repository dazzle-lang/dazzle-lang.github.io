Start with a small checkout example. You’ll keep a reference to an order number, follow two calls that place strings in different regions, and see what happens when its ownership moves.

1. [Reference safety](/tour/safety/) shows why a reference to an order number survives a total update and can become invalid when the queue grows.
2. [Automatic memory placement](/tour/memory-placement/) shows how the same helper builds a string in the region of whichever list it receives.
3. [Ownership and RAII](/tour/ownership/) explains destruction, copies, moves, and types that own resources.
4. [Errors as values](/tour/errors/) handles failures, optionals, and nullable pointers with one `or` clause.
5. [C and C++ interop](/tour/cpp-interop/) brings a native library into a Dazzle project from its own headers and build.
6. [Compiler tooling](/tour/tooling/) uses a diagnostic to explain and repair a missing ownership transfer.
